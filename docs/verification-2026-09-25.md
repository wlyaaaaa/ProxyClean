# 2026-09-25：一次点击关闭与可再次启动的验收

## 目标及边界

修复客户端关闭的重复确认、启动辅助服务被停后无法正常重新启动，以及关闭后 DNS 问题被笼统归为网络失败的缺口。覆盖飞鸟、Clash Verge 和原有定向清理保护。

本次续作明确保持现用 Clash Verge 运行。没有为验收关闭或重启现用代理、DNS 服务、远程服务、网卡或系统路由，也没有执行真实 DNS 缓存刷新。没有用本机在线关闭再打开冒充无影响测试。

## 回归覆盖

一次点击通过真实 GUI 函数完成只读预检、必要的同用户 UAC 衔接、自动继续及重复点击抑制。没有明确关闭请求时，普通入口和预览仍只读；多个客户端必须明确选择，授权不足不会循环请求。

客户端退出测试使用合成进程和服务：验证正常退出、同一身份的自动残留处理、PID 复用拒绝、端口接管、自然退出竞争、辅助服务恢复、停止或清理抛错、恢复超时、原本停止的服务不启动、独立核心服务不复活，以及恢复后核心重新出现时不报告成功。

DNS 验证区分连续解析错误、混合连接错误、HTTP 错误、工具缺失和站点回退。缓存仅属于明确关闭或显式缓存动作；即使客户端先清空设置，退出后仍执行缓存处理，失败保留明确警告。

注册表写入测试使用一次性的 `HKCU\Software\ProxyClean.Tests` 子键；Git 测试使用进程级临时配置；修改进程、服务、网卡和网络的动作均由测试替身承接。测试结束清理隔离资源，不覆盖用户配置。

## 未执行及不作出的承诺

没有关闭现用 Clash Verge，故不声称完成当前桌面的真实“关闭 → 浏览器直连 → 再次打开”端到端验收。关闭代理后，原本需要代理的网站不因此获得直连能力。没有执行影响桌面的 GUI 冒烟操作，也没有将本次代码自审描述为独立模型审查。

本次工作选择源码修复、异常路径回归、真实但不改变状态的联网检查和前后状态对照作为交付证据；不增加后台自动清理服务，不修改远程连接策略。

后续维护必须保留以上证据区别。新增客户端或变更服务识别时，先补相应的正常退出、失败恢复、重复启动和无副作用回归，不以进程消失或单个 HTTP 成功直接宣告全部恢复。
